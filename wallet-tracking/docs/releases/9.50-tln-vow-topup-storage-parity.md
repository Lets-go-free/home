# 9.50 – Gemeinsamer strenger Top-up-Storage-Nachweis

Build 20261122-104159 · 22.11.2026 10:41:59 CET.

Die Browser-Funktion `compareSameWalletPositionState` delegiert an den gemeinsamen `manualTopUpStorageContinuity`-Kern. Der Server wertet dieselbe Funktion ausschliesslich aus, wenn getrennte historische Lots mit unabhängig hinterlegten gezielten Storage-Zuständen vorliegen. Die Kriterien bleiben unverändert: gleicher Mapping-Root und Startoffset, Timestamp-Kontinuität des ersten Stakes, neuer Timestamp beim zweiten Stake, belegte vorherige Belegung und Änderung der Kernfelder, erhaltener erster State.

**Grenze:** Die Funktion sammelt keine neuen Storage-Belege. Aktuell vorhandene zusammengeführte Top-ups sind nicht automatisch erneut unabhängig nachprüfbar. Es gibt keine neuen oder geänderten kanonischen Positionen, Rewards, Claims, Cursors oder Cronjobs; `manualTopUpContinuityCandidates` ist ausschliesslich technische Receipt-Evidenz. Vollständige Browser-Discovery auf dem Server bleibt offen.

Installation: übliches Update-ZIP, danach Edge Function `tln-vow-reward-refresh` neu deployen. Keine SQL-Migration. Test `node tests/tln-vow-topup-storage-parity-950.test.mjs`.
