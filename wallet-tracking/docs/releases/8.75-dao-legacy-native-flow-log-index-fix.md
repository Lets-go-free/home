# WalletTracking 8.75 · Einzelübernahme Native-Flow `log_index` korrigiert

16.11.2026 (Schweizer Zeit). Korrektur der Version 8.74.

## Befund

8.74 wurde installiert, die service-only SQL-Funktion ausgeführt und die Edge Function deployed. Die erneute lesende Live-Prüfung für TX `0xc27e0aa5e092efefe9f57e8c7d6890bfdd54a974fde2988e6319a653b3eb2363` ergab weiterhin gültige Mint-, Eigentums- und exact-v13-Preisbelege (15.167495057030400213 APTM, 1.3088042775902748 USD/APTM).

Die erste ausdrücklich bestätigte Übernahme schlug fehl mit:

`null value in column "log_index" of relation "project_transaction_asset_flows" violates not-null constraint`

Read-only-Datenbankkontrolle danach: `unassigned_legacy / pending / pending`, `nft_id=NULL`, **0** kanonische Claims, **0** Asset-Flows, **0** Preisanker. Kein teilweiser Import.

## Korrektur

- SQL `20261116195516_dao_legacy_native_log_index_fix_875.sql` ersetzt die eine in 8.74 eingeführte service-only Funktion. Ein synthetischer Native-Flow benutzt nun `log_index=-1`, exakt wie der bestehende Builder `dao-reward-refresh/index.ts`. Alle anderen Schutzabfragen, atomaren Rollbacks und der feste TX-Scope bleiben unverändert.
- Admin-JavaScript zeigt künftig die eigentliche JSON-Fehlermeldung eines nicht erfolgreichen Edge-Aufrufs an, ohne automatische Wiederholung.
- Release-Anzeige und Doku aktualisiert. Keine Edge-Function-Änderung; nach Installation genügt die neue SQL-Migration, danach kontrollierter Test.

## Reihenfolge

1. ZIP 8.75 in GitHub installieren.
2. Neue SQL-Migration im Supabase SQL Editor ausführen. **Migration führt keinen Claim-Commit aus.**
3. Admin-UI neu laden, Live-Einzel-Preview für #818 ausführen, prüfen und erst dann explizit erneut die Übernahme bestätigen.
4. Read-only Datenbankkontrolle: exakt ein neuer kanonischer Claim mit zugehörigem Preis und Flow, ursprüngliche übrigen 75 Legacy-Kandidaten unverändert.

DAO-Cron/Live-Worker ausgeschaltet lassen. Bei erneutem Fehler keine Wiederholung ohne DB-Nachprüfung.
