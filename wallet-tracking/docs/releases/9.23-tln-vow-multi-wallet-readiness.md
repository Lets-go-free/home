# Phase 9.23 – Read-only Mehr-Wallet-Bereitschaft für TLN/VOW-Rewards

**Build:** 20261119-204746 (Schweizer Zeit)

## Ausgangslage

- Der 9.22-Top-up-Reward wurde im zweiten Benutzerkonto produktiv bestätigt.
- Die bisherige Edge-Funktion hat nur einen Ein-Wallet-Delta-Preview ohne Persistenz.
- Sie liest Service-Role-geschützt vorhandene `verified-discovery-results` über verschiedene Benutzer. Ein Snapshot ist **kein** Nachweis, dass sämtliche verschlüsselten TLN/VOW-Wallets erfasst sind.
- Historische `completedStep`-/`done`-Flags bescheinigen keine unabhängige Scan- oder Reward-Abdeckung.

## Neuer geschützter Modus

POST `{"mode":"multi-wallet-readiness","maxBlocks":5000}` an die bereits installierte Edge-Funktion `tln-vow-reward-refresh` mit unverändertem Header `x-tln-reward-secret`.

Ergebnis:

- `summary.snapshotWallets`, `readyForPlanning`, `legacyWithoutCoverage`, `incompleteWorkflow`, `invalidSource`, `stale24h`, `stale48h`.
- Für höchstens 25 nach Alter geordnete, unabhängig vollständig verifizierte Snapshots: anonyme Ordinalzahl und **hypothetisches** erstes Chunk-Fenster von maximal `maxBlocks`.
- Nur wenn wirklich verifizierte Quellen vorliegen: ein RPC-Aufruf `eth_blockNumber` für die aktuelle BSC-Blockhöhe.
- Weder Wallet-/Benutzeridentitäten noch Secrets oder Roh-Cachedaten in der Antwort.

**Nicht enthalten:** Auflistung aller verschlüsselten Wallets, Live-Scanning, Reward-Klassifikation, Cache-/Cursor-/Lease-Writes, Cron. Ein leerer Plan ist bei allen Legacy-Snapshots das *korrekte* Ergebnis und kein Beweis, dass keine Rewards existieren.

## Abnahme

1. Versionierte Dateien installieren und Edge-Funktion mit vollständig eingebettetem Shared Core deployen.
2. Read-only POST mit `{"mode":"multi-wallet-readiness"}` ausführen; vollständiges JSON prüfen.
3. Bis zur vollständigen Freigabe Cron deaktiviert belassen. Erst anschliessend benutzerspezifische Wallet-Berechtigung, tatsächliche Scan-Fortschritte und Commit-/Retry-Semantik entwickeln.

Lokaler Test `node --experimental-strip-types tests/tln-vow-multi-wallet-readiness-923.test.mjs`: bestanden (Proof-Gate, Legacy-/Fehler-/Workflow-Kategorien, 100-Block-Grenze, keine Adressausgabe oder Writes).
