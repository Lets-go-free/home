# WalletTracking 9.14 — BSC RPC Filterdiagnose (read-only)

Build: 20261118-222733 (Europe/Zurich)

## Ausgangslage

- Version 9.13 läuft auf der produktiven Edge Function `tln-vow-reward-refresh`.
- `delta-scan-preview` mit `maxBlocks:100` lieferte für den BSC-Provider HTTP 400 ohne JSON-RPC-Code. Kein Cursor oder Cache wurde verändert.
- Aus HTTP 400 allein lässt sich noch nicht schließen, ob ein Contract-Array, Topics, historische Log-Daten oder die API-/Plan-Konfiguration verantwortlich ist.

## Neu: `mode=rpc-diagnostic`

- Authentifizierung wie zuvor über `x-tln-reward-secret`; gleiche festgelegte Wallet aus dem verifizierten Snapshot.
- Der Modus plant **maximal 100 historische Blöcke**, auch wenn `maxBlocks` größer angegeben wurde.
- Sechs fest definierte, rein lesende Provider-Anfragen: `eth_chainId`; historischer Einzelblock mit einem bekannten Contract und Transfer-Topic; historische 100-Blöcke-Abfrage mit einem Contract; mit vier Contract-Adressen; mit zusätzlichem Wallet-Topic; aktueller Einzelblock mit einem Contract.
- Je Test werden nur Erfolg/Fehlerkategorie, HTTP-Status, JSON-RPC-Code, Log-Anzahl und BSC-Chain-ID-Übereinstimmung ausgegeben. Keine rohe RPC-Antwort, Provider-URL, Secret, Wallet-Adresse oder Transaktionsdetails.
- Zeitlimit pro Test: 6,5 Sekunden. Die Tests können abhängig vom Provider etwas dauern.
- Kein Reward-/Referral-Klassifizieren oder -Importieren, keine persistierten Logs, keine Datenbank-/Cursor-Schreibzugriffe, **kein Cron**.

## Bedienung nach Installation und Edge-Deploy

POST an `tln-vow-reward-refresh`, Header `x-tln-reward-secret`, Body `{"mode":"rpc-diagnostic","maxBlocks":100}`.
Die Antwort enthält `diagnosis.probes` mit den sechs getrennten Prüfergebnissen. Eine `ok:true`-Antwort sagt nur, dass die Diagnose durchgeführt wurde; einzelne Probes können weiterhin 400 oder andere Fehler melden.

## Interpretation

- Bereits historischer Einzelblock-Logtest mit HTTP 400: eher grundsätzliche Provider-/API- oder historische Log-Beschränkung; Array-/Topic-Komplexität noch nicht schuld.
- Historische Anfragen scheitern, aktueller Einzelblock funktioniert: möglicher Anbieter-/Tarif-/Historien-Limit.
- Einzelcontract funktioniert, Contract-Array scheitert: Filter-Kompatibilität prüfen.
- Contract-Array funktioniert, Wallet-Topic scheitert: Topic-Filter/Provider prüfen.
- Alle Probes erfolgreich, ursprünglicher `delta-scan-preview` scheitert weiter: zweite Richtung / Zeitfenster / Rückgabevalidierung separat prüfen.

Das sind Diagnosehinweise, keine automatischen Ursachenbeweise.
