## Ziel

Keine 20 manuellen Supabase-Test-Aufrufe mehr. Im Admin → Audit befindet sich ein expliziter Start-/Stopp-Bereich, der den **bereits live getesteten Modus 8.45** wiederholt aufruft. Keine Änderungen an der Edge Function oder der SQL-Verifikationsfunktion.

- Pro Aufruf maximal 3×4 Auszahlungen; maximal 25 sequenzielle Aufrufe pro manuellem Start (also bis 300 Auszahlungen).
- Bereits verifizierte Kandidaten überspringt der bestehende Server-Modus. Bei `no_pending` endet die Verarbeitung. Bei `time_budget` darf nur mit positiven, konsistenten Ergebnissen weitergemacht werden.
- Ungültige API-Antwort, HTTP-/Netzwerkfehler, nicht verifizierter Kandidat, abgebrochene Admin-Sitzung oder inkonsistente Zähler führen zum sofortigen Anhalten **ohne automatisches Retry**.
- Der Stopp-Knopf beendet nach dem aktuellen Server-Aufruf (nicht mitten in einer bereits laufenden Blockchain-Prüfung).
- Tab muss offen bleiben; Browser/Computer dürfen die Verarbeitung nicht unterbrechen. Dies ist **keine Hintergrundautomatisierung**. Neu starten setzt bei den offenen Kandidaten fort.
- Zweckgebunden an Wallet `8a3c5dc6-0610-482d-a327-3f3ba03db158` und nur für eingeloggte Admins. Server prüft Admin-JWT unverändert.
- Kein Edge-Function-Deployment, keine SQL-Migration, keine Cron- oder Live-Worker-Aktivierung. Keine kanonischen Rewards, USD-Preise, NFT-Zuordnungen oder Referral-Postings.
