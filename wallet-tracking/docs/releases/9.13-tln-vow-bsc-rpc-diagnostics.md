# WalletTracking Phase 9.13 — BSC-RPC-Diagnose und begrenzte Delta-Scans

Build: 20261118-221933 (Europe/Zurich)

## Anlass

9.12 ignorierte `maxBlocks` und überschrieb die Diagnose einer HTTP-Fehlerantwort von Alchemy mit einem ungenauen Fehlertext. Der 100-Block-Test führte daher erneut 5'000 Blöcke aus.

## Umfang

- `delta-scan-preview`: `maxBlocks` 1–5000, Standard 5000; ungültige Werte werden abgelehnt.
- `delta-preview`: gleicher steuerbarer Chunk-Plan zur Kontrolle.
- Bei `eth_getLogs`-Fehlern: sichere Felder `rpcDiagnostic.phase/category/httpStatus/rpcCode`. Keine URL, API-Keys, Wallet oder ungefilterten Antwortkörper.
- Kein RPC-Fallback, kein Cron, keine Datenbankmigration, keine Reward- oder Cursoränderung.

## Abnahme

1. ZIP deployen und `tln-vow-reward-refresh` neu deployen.
2. Mit vorhandenem `x-tln-reward-secret` `{"mode":"delta-scan-preview","maxBlocks":100}` testen.
3. Prüfen: `chunk.blocks <= 100`; bei Fehler `rpcDiagnostic` statt nur generischer Meldung.
4. Danach RPC-Provider/Plan oder Filter gezielt korrigieren, keine weitere Verdichtung auf Verdacht.
