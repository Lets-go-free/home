# WalletTracking 7.91 – manueller DAO-Test mit Admin-JWT

- `dao-reward-refresh`: ausschliesslich `mode: inspect-test-wallet` akzeptiert ein gültiges Benutzer-JWT **ohne** `x-wallet-refresh-secret`, sofern `DAO_REWARD_ENABLE_TEST_INSPECT=true` gesetzt ist.
- Der Benutzer muss in `public.admins` über dieselbe `auth.users.id` als Admin hinterlegt sein. Adminrechte werden im Service-Role-Backend anhand der UUID geprüft, nie anhand eines Client-Flags.
- Die Testadresse ist im Servercode fest auf die bekannte Referral-Adresse beschränkt und nicht durch den Request änderbar. Der Test liest ausschliesslich aggregierte Daten.
- Jeder andere Request verlangt weiterhin `WALLET_DAILY_REFRESH_SECRET`. `DAO_REWARD_ENABLE_LIVE_WORKER=false` beibehalten; kein Cron.
- In Supabase Edge Functions `dao-reward-refresh` **neu deployen** (Code `supabase/functions/dao-reward-refresh/index.ts`). Verify JWT eingeschaltet lassen.
- Für den manuellen Test POST mit Body `{"mode":"inspect-test-wallet"}`, `Content-Type: application/json`, `Authorization: Bearer <gültiges Benutzer-Access-Token>` schicken. **Keinen** Secret-Wert in den Chat kopieren.
- Wenn Test-Dialog keine Benutzer-JWT-Option hat, keinen Service-Role-Key als Benutzer-JWT einsetzen. Stattdessen Benutzer-Access-Token aus einer sicheren authentifizierten Sitzung verwenden.
- Ergebnisse: 200 (Erfolg), 401 (kein/abgelaufenes User-JWT), 403 (kein Admin oder Test nicht aktiviert), 500 (technischer Fehler). SQL-Migration ist nicht notwendig.
- Nach Test `DAO_REWARD_ENABLE_TEST_INSPECT=false` setzen. Es wurde kein Cron aktiviert und keine Reward-Daten verändert.
