# Phase 9.18 – Supabase-Editor-Deploy repariert

## Fehler aus 9.17

Der Supabase-Dashboard-Editor konnte den relativen Import
`../../../js/tln-reward-verification-core.js` aus der Edge Function nicht
auflösen. Das Deployment scheiterte vor dem Start mit `Module not found`.

## Korrektur

- Die Edge Function `supabase/functions/tln-vow-reward-refresh/index.ts` ist
  wieder vollständig als **eine Datei** deploybar; kein lokaler Modulimport.
- Die kanonische Prüflogik steht weiterhin in
  `js/tln-reward-verification-core.js` und wird vom Browser direkt verwendet.
- `tools/build-tln-reward-edge.mjs` generiert dieselbe Prüflogik in den
  gekennzeichneten Abschnitt der Edge Function. Eine Änderung der Regeln
  wird nur an der kanonischen Datei vorgenommen. Der Generator und der
  Regressionstest prüfen die inhaltliche Übereinstimmung.
- Keine Änderung der Reward-Klassifikation, Cursor, SQL, Geheimnisse oder
  Cron-Einstellungen.

## Installation / Test

1. ZIP 9.18 installieren.
2. Inhalt der neuen `supabase/functions/tln-vow-reward-refresh/index.ts`
   im Supabase-Dashboard-Editor deployen.
3. Danach Read-only-POST `{"mode":"snapshot-verification-audit"}` mit dem
   bereits vorhandenen Secret-Header testen.

Lokale Tests 9.15–9.18 bestanden. Dashboard-Deployment bleibt bis zum
Benutzertest unbestätigt.
