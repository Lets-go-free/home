# WalletTracking 7.92 — Kontrollierter DAO-Einzel-Wallet-Import

Build: 20261107-172219 (Schweizer Zeit)

## Testmodus

- POST `{"mode":"import-test-wallet"}`, Admin-JWT erforderlich.
- `DAO_REWARD_ENABLE_TEST_IMPORT=true` ist für die Testdauer notwendig.
- `DAO_REWARD_ENABLE_LIVE_WORKER=false` bleibt zwingend.
- Die Wallet-Adresse ist serverseitig unveränderlich auf `0x239c5822a0d2A67E629D7A3b5C8180721E228B47` begrenzt. Nur **genau eine** dazu passende registrierte Wallet wird akzeptiert.
- Pro manueller Ausführung maximal eine Explorer-Seite je Datenstrom (Transaktionen, ERC-20, gezielte Referral-Transfers).
- Neue Rohtransaktionen, Asset-Flows und Claim-Kandidaten werden nur bei Nichtvorhandensein gespeichert; eigene Scanner-Cursor werden fortgeschrieben. Bereits vorhandene Transaktionen/Flows werden nicht geändert.
- Es werden **keine** Reward-Summen, Preise, Snapshots, Bot-Zuordnungen oder täglichen Queue-Zustände verarbeitet.
- `inspect-test-wallet` bleibt als rein lesende Kontrollfunktion verfügbar. Vor und nach dem Test ausführen.
- Während des manuellen Imports bitte keine zweite gleichzeitige Ausführung starten; Wiederholungen sind idempotent bezüglich der eindeutigen Ereignisschlüssel.
- Nach dem Test `DAO_REWARD_ENABLE_TEST_IMPORT=false` setzen; keinen Cron aktivieren.

## Sicherheit und Freigabe

Dieser Modus ist kein produktiver Reward-Job. Der Import ist absichtlich auf Rohdaten begrenzt, und ein fehlgeschlagener Lauf kann bereits einzelne Rohdaten/Checkpoints geschrieben haben. Die vollständige fachliche Reward-Verarbeitung benötigt gesonderte Freigabe und Live-End-to-End-Vergleich.
