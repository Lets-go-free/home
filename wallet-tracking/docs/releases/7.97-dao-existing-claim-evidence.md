# WalletTracking Phase 7.97 – kanonische Claim-Evidenz

Prüffrage: Können die 288 noch nicht gekennzeichneten, aber bepreisten Claims anhand derselben Transaktion UND eines exakten nativen Geldeingangs bereits als kanonisch vorhanden markiert werden?

`reconcile-test-wallet` ist vollständig lesend. Eine bereits vorhandene USD-Bewertung oder NFT-ID ist kein selbständiger Payout-Beweis. Der separate SQL-Schritt verengt die zulässige Kennzeichnung auf native Zahlungen, exakte Token-Dezimalstellen und exakt passenden on-chain Betrag. Alte ERC20-Claims werden nicht pauschal als native APTM-Auszahlungen markiert.

Ablauf: SQL-Migration einmalig im Supabase SQL Editor anwenden, Edge Function aktualisieren, manuellen Read-only-Test mit Admin-JWT und `DAO_REWARD_ENABLE_TEST_INSPECT=true` ausführen. Erst danach über manuelle Kennzeichnung entscheiden.

Die Migration enthält eine einzige Funktionsdefinition und keine SELECT-Resultsets.
