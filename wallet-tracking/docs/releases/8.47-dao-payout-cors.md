# WalletTracking 8.47 – DAO-Verifikation: Browser-CORS

Stand: 14.11.2026 17:09:05 CET; Build 20261114-170905.

## Fehlerursache und Änderung

Bei 8.46 meldet Admin → Audit nach dem ersten Aufruf `Failed to send a request to the Edge Function`; der direkte Supabase-Test des unveränderten Modus `verify-native-payout-multi-batch-845` funktioniert. In `dao-reward-refresh/index.ts` werden bei der Batch-Route alle JSON-Antworten ohne `Access-Control-Allow-Origin` gesendet, obwohl der OPTIONS-Preflight diesen Header besitzt. Browser dürfen die eigentliche Antwort deshalb nicht lesen.

8.47 ergänzt nur für die 8.44/8.45-Verifikationsroute die vorhandenen `metadataCors`-Header zu Erfolgs- **und** Fehlerantworten (inkl. 400, 401, 403, 404, 409, 500). Kein geändertes Selektionskriterium, keine RPC- oder Explorer-Verifikationsänderung, keine neue API-Berechtigung; CORS ist kein Authentifizierungsersatz, Admin-JWT wird weiter serverseitig geprüft. Keine SQL-Migration.

## Installation

1. ZIP in Website-Verzeichnis einspielen (neue `index.html`, Edge-Quellcode, Tests, Dokumentation).
2. **Die geänderte Edge Function `supabase/functions/dao-reward-refresh/index.ts` separat auf Supabase deployen**, inklusive existierender Import-Abhängigkeiten. Das ZIP-Update allein aktiviert CORS in Supabase nicht.
3. App hart laden, unten Phase 8.47 und Build 20261114-170905 prüfen.
4. Im Browser zunächst eine einzelne manuelle Verifikation im Admin → Audit auslösen; angezeigte Server-Antwort und DB-Zähler validieren, erst dann den Langlauf zulassen.
