# Phase 9.09 – 18.11.2026 21:20:18 CET

## TLN/VOW: sicherer erster Server-Schritt

Neue Edge Function `tln-vow-reward-refresh`, **ausschliesslich PREVIEW**, liest verifizierte BSC-Discovery-Snapshots und gibt nur aggregierte Aktualitätsdaten zurück. Sie nutzt einen separaten Header `x-tln-reward-secret` (`TLN_REWARD_CRON_SECRET`), benötigt `SUPABASE_URL` und `SUPABASE_SERVICE_ROLE_KEY`, und darf nur mit ausgeschalteter JWT-Verifikation und gesetztem Geheimnis deployed werden.

**WICHTIG:** Sie scannt KEINE Blockchain, aktualisiert KEINE Rewards, Cursor oder Snapshots und richtet KEINEN Cron ein. Kein automatischer Rewards-Job ist mit diesem Release fertiggestellt. Der Code bereitet nur einen beobachtbaren Read-only-Einstieg vor. `wallet_reward_refresh_attempts` wird nicht beschrieben und DAO bleibt unberührt.

Der Server-Lauf kann derzeit nicht dieselbe Reward-Berechnung wie die bestehende browserbasierte Discovery reproduzieren. Bis zur verifizierten Portierung der Schritte Staking, Rewards, Referral, Bonus samt Delta/Overlap muss die tägliche produktive Verarbeitung deaktiviert bleiben.

### Installationsreihenfolge
1. Webdateien nach GitHub übernehmen (wenn es die kombinierte App-Version sein soll).
2. Separates Secret `TLN_REWARD_CRON_SECRET` in Supabase setzen, Edge-Funktion `tln-vow-reward-refresh` deployen (JWT-Verifikation aus, geschützt durch Secret). **Keine pg_cron-Einrichtung.**
3. Mit einem autorisierten POST und Header `x-tln-reward-secret` im geschützten Testweg eine aggregierte Preview prüfen.
