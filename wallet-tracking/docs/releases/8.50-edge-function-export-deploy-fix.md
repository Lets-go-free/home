# WalletTracking 8.50 — Korrektur Edge-Function-Deployment

Erstellt: 14.11.2026 20:01:08 CET

## Fehler und Diagnose
Supabase-Edge-Funktion `dao-reward-refresh` brach beim Start ab (`BOOT_ERROR` / HTTP 503):
`The requested module './price-target-worker.ts' does not provide an export named 'processExactPriceTargets'`.
Der vollständige und korrekte Export befindet sich bereits in 8.48; das inkrementelle ZIP 8.49 enthielt nur die geänderte `index.ts` und nicht die unveränderte Worker-Datei. Beim Dashboard-Deployment lag damit offenbar keine passende Worker-Datei vor.

## Korrektur
- `index.ts` der Phase 8.49 **unverändert im Verhalten** erneut ausgeliefert.
- `price-target-worker.ts` der Phase 8.48 **unverändert im Verhalten** erneut beigefügt; mit explizitem `export async function processExactPriceTargets(...)`.
- Release-/Build-Anzeige Phase 8.50 aktualisiert.
- Keine neue SQL-Migration; die bereits installierte Migration 8.49 **nicht** erneut ausführen.
- Keine Änderung an Claim-, Reward-, NFT- oder Preisdaten durch das Paket.

## Deployment / Test
Beide Dateien innerhalb **derselben** Edge Function `dao-reward-refresh` deployen. Im Supabase-Dashboard muss die Datei `price-target-worker.ts` in der Funktionsdateiliste sichtbar sein und den Export enthalten. Bestehende weitere Importe/Module der Edge Function beibehalten. Danach zuerst den Boot-Test mit `admin-miner-claim-preview-849` und entsprechender `walletId` ausführen, ohne Live-Worker/Cron zu aktivieren. Vor einer Übernahme stets Vorschau prüfen.

## Noch offen
- Boot-/Vorschautest von 8.50 in Supabase; Live-Umgebung konnte hier nicht geprüft werden.
- Erster kontrollierter 1-Claim-Test der historisch verifizierten Mining-Finalisierung erst nach erfolgreicher Vorschau.
- Weitere kanonische Reward-Übernahme nur nach erneuter Kontrolle.
- DAO-Cron und Live-Worker bleiben deaktiviert.
