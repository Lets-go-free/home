# WalletTracking 7.81 – Unzugeordnete neue Miner-Claims

## Problem

Die DAO-Staging-Queue legte nur Claim-Kandidaten mit einer eindeutigen NFT-ID an. Ein neuer Miner-Claim ohne eine solche ID wurde verworfen, bevor seine Auszahlung geprüft werden konnte. Damit konnten gültige neue Miner-Ereignisse beim inkrementellen Scan verloren gehen.

## Änderung

- `Miner Claim` ohne nachgewiesene NFT-ID wird mit `status=unassigned_miner` und `nft_contract/nft_id=NULL` in `dao_reward_claim_candidates` angelegt.
- Ein Claim mit nachgewiesener Kandidaten-ID bleibt im bisherigen `pending`-Pfad mit historischer Besitzprüfung.
- Legacy-Claims ohne eindeutige NFT-ID werden bewusst **nicht** automatisch zu neuen Minern umklassifiziert.
- Auszahlungsnachweise (`payout_status`, Token-Adresse, exakter Rohbetrag, Dezimalstellen, Transferzahl) werden für `ownership_verified` **und** `unassigned_miner` geprüft. Ein Nachweis belegt nur die Zahlung, nicht den Bot.
- Bestehende `project_transactions`, `project_transaction_asset_flows`, Preise, Summaries und manuelle Snapshots werden nicht verändert.
- Migration erweitert ausschliesslich die vorhandene service-role-geschützte Tabelle; RLS/Grants bleiben unverändert.

## Betrieb / Test

Die SQL-Migration ist **vor** einem späteren Deployment des Workers erforderlich. Der Worker ist weiterhin nicht freigegeben: die vollständige kanonische Claim-/Referral-Zuordnung, einheitliche historische Preisbewertung, TLN/VOW-Worker und Live-End-to-End-Test fehlen.

Lokale Tests: `node --test tests/dao-*test.mjs`; 42 bestanden. Keine Datenbank-/Blockchain-Live-Verifikation.
