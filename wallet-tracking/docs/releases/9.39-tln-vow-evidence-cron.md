# WalletTracking 9.39 – Inaktive automatische Beleg-Jobs

Build 20261120-113941 (Europe/Zurich).

## Lieferung

- Versionierte ZIP-Datei installieren.
- Neue Migration `supabase/migrations/20261120104700_tln_vow_reward_evidence_jobs_939.sql` in Supabase SQL Editor ausführen.
- Standalone Edge Function `tln-vow-reward-refresh` mit `supabase/functions/tln-vow-reward-refresh/index.ts` erneut deployen.

Die Migration legt **zwei inaktive** pg_cron-Jobs an. Es erfolgt durch die Installation kein automatischer Netzwerklauf:

| Job | Zeitplan (UTC) | Modus |
|---|---|---|
| `tln-vow-evidence-stage-5m` | `3-59/5 * * * *` | `delta-work-cycle` |
| `tln-vow-evidence-receipts-5m` | `4-59/5 * * * *` | `delta-receipt-verify` |

Der zweite Job läuft eine Minute nach dem ersten, um aufgelaufene Receipt-Checks nachzuholen. Beide bearbeiten nur die 9.36-/9.37-Staging-Tabellen und **keine** kanonischen Reward- oder Referral-Daten.

## Vault-Voraussetzung vor Aktivierung

- `tln_vow_trade_sync_url`: bestehende Supabase-URL aus dem aktiven Trade-Sync-Job; wird wiederverwendet.
- `tln_vow_reward_refresh_auth`: **neues** Vault-Secret mit genau demselben Wert wie `TLN_REWARD_CRON_SECRET` der Edge Function. Der Wert gehört ausschliesslich ins Vault und niemals in die Migration oder Logausgaben.

Status ohne Ausgabe der Secrets prüfen:

```sql
select j.jobname,j.schedule,j.active,
       (select count(*)=1 from vault.decrypted_secrets
        where name='tln_vow_trade_sync_url') as url_vorhanden,
       (select count(*)=1 from vault.decrypted_secrets
        where name='tln_vow_reward_refresh_auth') as auth_vorhanden
from cron.job j
where j.jobname in ('tln-vow-evidence-stage-5m','tln-vow-evidence-receipts-5m')
order by j.jobname;
```

Erst nach erfolgreicher Secret-Prüfung und einem geschützten Test darf der separate Staging-Cron gezielt aktiviert werden. **Aktivierung ist bewusst nicht Teil von Release 9.39.**

## Weitere Arbeit

Dieser Job sammelt und verifiziert nur Transfer-/Receipt-Daten. Er ist **nicht** die fertige tägliche Reward-Ermittlung: Browser-spezifische Claim-/State-/Lifecycle-/Referral-Beweise, Vollständigkeit über verschlüsselte Wallets, kanonische idempotente Reward-Zuordnung und Vergleich mit manueller Discovery bleiben offen. Der produktive TLN/VOW-Rewards-Cron bleibt aus.

Technische Korrektur im Edge-Worker: bei zu vielen Treffern wird das Alchemy-Blockfenster jetzt bis auf einen Block verkleinert. Selbst ein zu dichter Einzelblock darf keinen unvollständigen Fortschritt speichern.
