# WalletTracking 9.40 – Automatischer Belegabgleich mit manuellen Reward-Proofs

Build 20261120-140941 (Europe/Zurich).

## Änderung

- Dieselbe reine `reconcileVerifiedTopUpReceipt`-Regel steht im Browser-Core und in der daraus generierten Supabase Edge Function zur Verfügung.
- Bei **jedem neuen** automatischen Receipt-Verarbeitungsschritt (regulärer Work-Cycle und Receipt-Backlog) werden die bestätigten On-chain-Logs mit bereits vorhandenen **eindeutigen** manuellen Top-up-Storage-Proofs sowie den dazugehörigen Reward-Evidenzzeilen abgeglichen.
- Ergebnisse werden als `manualRewardProofMatches` im **technischen Receipt-Staging-JSON** gespeichert. Die API meldet die Anzahl der Matches. Keine neue SQL-Migration nötig.
- Nicht nachweisbare, doppelte, gebridgte oder mehrdeutige Mints werden abgewiesen. Auch ein Match alleine bestätigt noch nicht die exakte Menge oder vollständige Rewards-Coverage.

## Installation und Sicherheit

1. ZIP installieren (Phase/Build aktualisiert).
2. Edge Function `tln-vow-reward-refresh` aus der vollständig gebündelten `index.ts` neu deployen. **Nicht** manuell nur Teilmodule in Supabase kopieren.
3. Beide bereits aktiven Evidence-Crons laufen unverändert weiter. Keine Migration und kein neues Secret.

Wichtig: **Das ist eine automatische, konservative Klassifizierungs-Vorstufe**, keine vollständige tägliche TLN/VOW-Rewards-Engine. Neue Rewards ohne vorheriges Browser-Proof bleiben ungeklärt. Keine Claims/kanonischen Rewards, kein historischer Verifikationscursor und kein Referral-Payout werden geändert. Der eigentliche TLN/VOW-Reward-Cron bleibt deaktiviert.
