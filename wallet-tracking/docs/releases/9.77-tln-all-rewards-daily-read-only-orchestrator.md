# WalletTracking 9.77 – Gemeinsamer täglicher TLN/VOW-Prüfablauf

Stand: 23.11.2026 07:43:34 CET · Build 20261123-074334

## Umsetzung

Neuer geschützter Edge-Modus `daily-all-rewards-preview`: ruft **in derselben
Edge-Function** nacheinander die **bestehenden** Finalizer mit `commit:false` auf:

1. `daily-direct-claim-cycle` (direkte Staking-Claims)
2. `daily-bonus-claim-cycle` (Bonus)
3. `referral-claim-finalize` (Referral)
4. `indirect-claim-finalize` (indirekte Staking-Claims)

Jeder Teilpfad verwendet unverändert seine bestehende manuelle/shared
Prüflogik und verlangt eine vollständige gespeicherte Receipt-Inventur.
Fehlgeschlagene, unvollständige oder anders als Dry-Run beantwortete Teilpfade
blockieren die Gesamtvorschau; im Fehlerfall **keine** weiteren Pfade.
`commit:true` wird für den kombinierten Modus explizit abgewiesen.
Keine Ledger-, Snapshot-, Cursor-, Reward- oder Cron-Schreibzugriffe.

Das Ergebnis signalisiert ausdrücklich `canEnableWritingCron:false`, selbst
wenn alle vier Teilpfade 200/ok liefern: **historische Vollständigkeit, alle
verschlüsselten Wallets, positive Reward-Fälle, atomic cross-ledger writes**
sind weiterhin nicht verifiziert. Vier Einzel-Ledger bieten keine gemeinsame
Datenbanktransaktion; ein schreibender Orchestrator wäre daher vorzeitig.

## Migration

`20261123074334_tln_vow_daily_all_rewards_preview_disabled_977.sql` erstellt **einen zusätzlich inaktiven** Cronjob
`tln-vow-all-rewards-preview-daily` (03:10 UTC / 04:10 CET).
Die drei vorhandenen täglichen, schreibenden Jobs bleiben deaktiviert.
Die Migration stoppt, wenn ein solcher Schreibjob bereits aktiv ist.
Die laufenden Evidence-Jobs bleiben unverändert.

## Abnahme

ZIP installieren → SQL ausführen → Edge Function neu deployen → über
den bestehenden Vault-basierten SQL-Aufruf `{"mode":"daily-all-rewards-preview"}`
rein lesend prüfen. Auswertung: `pathsChecked=4`, `status=preview_only`,
`canEnableWritingCron=false`, `claimsCreated=0`. Auch bei 0 Receipts ist dies
nur ein **technischer** Leertest und keine fachliche Abnahme.

## Offene Arbeit

Vollständige Wallet-Abdeckung und historische Nachweise; positiver
Regressionstest für jeden Rewardtyp; sichere gemeinsame Commit-Freigabe bzw.
transaktional abgestimmte Ledgers. Kein täglicher Reward-Cron wird aktiviert.
