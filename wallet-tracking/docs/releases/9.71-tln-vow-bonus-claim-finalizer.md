# 9.71 · Bonus-Claim-Finalizer

## Installation

1. ZIP installieren.
2. SQL `supabase/migrations/20261122222003_tln_vow_bonus_claim_ledger_971.sql` in Supabase ausführen.
3. Edge Function `tln-vow-reward-refresh` neu deployen (Datei `supabase/functions/tln-vow-reward-refresh/index.ts` vollständig übernehmen).
4. Über den bereits funktionierenden authentifizierten SQL-HTTP-Test an die Edge Function `{"mode":"daily-bonus-claim-cycle"}` senden (kein `commit`).

## Erwartete Antwort

- `ok:true`, `mode:"daily-bonus-claim-cycle"`, `dryRun:true` und `receiptInventoryComplete:true`.
- `eligibleBonusClaims` kann bei derzeit fehlendem aktivem Staking **0** sein; das ist kein Vollständigkeitsbeweis.
- Kein Claim wird durch den Test geschrieben. Erst bei unabhängig geprüftem positivem Fall wäre ein explizites `commit:true` zu besprechen.

## Sicherheitsgrenzen

- Bereits manuell in `provenRewardRows` belegte Tx/Token-Paare werden ausgelassen; rohe Einzahlungen ohne explizite Bonus-Methode zählen nicht.
- Es werden nur bis zu 4'000 vollständige Receipt-Zeilen verarbeitet; bei unvollständiger Pagination wird abgebrochen.
- Historische Blockzeit wird nur bei explizitem Commit auf der Chain geprüft. Fehler oder Budgetüberschreitung verhindern den Commit.
- Noch keine automatische Bonus-Ledger-Anzeige in der UI, keine indirekten Reward-Claims, keine historische Vollständigkeitsbescheinigung und kein täglicher Cron.
