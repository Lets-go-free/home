# Phase 9.67 – Exakte Referral-Mint-Zahlungsbelege

Build 20261122-213915 · 22.11.2026 21:39:15 CET.

Der laufende serverseitige Receipt-Prozess ermittelt bei bereits via **gemeinsamer manueller Step-5-Regel** als stark klassifizierten Referral-Mints den Betrag direkt aus den erfolgreich verifizierten ERC-20-Transfer-Logs der Transaktion. Pro Token werden nur Zero-Address-Mints an die untersuchte Wallet berücksichtigt:

- `mintAmountRaw`: Summe aller passenden Mint-Logs als exakter Ganzzahlstring, keine verlustbehaftete Float-Rundung.
- `mintLogIndexes`: eindeutige Receipt-Log-Indizes der zugehörigen Mint-Logs.
- `walletNetRaw`: Nettofluss dieses Tokens an die Wallet über alle Receipt-Logs. Muss positiv sein.
- `receiptVerified`: Nachweis, dass alle Staging-Transfer-Ereignisse mit der Blockchain-Receipt übereinstimmen.
- Vorhandene Flags `referralPathVerified`, `referralLevel` und `referralPathEvidence` bleiben unverändert.

Die Belege werden in der **bereits existierenden** `tln_vow_reward_receipt_stage.evidence.referralMintCandidates` gespeichert. Keine neue Klassifizierungsheuristik und keine Tabellenänderung. Kein automatischer Claim-Commit, keine Änderung an bereits gebuchten manuellen Rewards und keine Aktivierung des täglichen Reward-Crons.

## Installation

ZIP installieren und ausschliesslich Edge Function `tln-vow-reward-refresh` neu deployen. **Kein SQL nötig.** Der bestehende 5-Minuten-Job verwendet die neue Belegablage für **neu** verifizierte Receipts automatisch. Alte bereits gespeicherte Receipts werden nicht stillschweigend überschrieben.

Regressionsprüfung: `tests/tln-vow-referral-mint-amount-evidence-967.test.mjs` testet mehrere Mint-Logs, exakte Beträge, Nettobetrag, doppelte Log-Indizes und unbestätigte Receipts.

**Offen:** Sichere kanonische Übernahme belegter Referral-Mint-Zahlungen in die Reward-Übersicht und vollständige historische Wallet-/Referral-Abdeckung. Es gibt zurzeit laut Live-Job keine neuen Mint-Kandidaten; kein positiver Live-Abnahmetest möglich.
