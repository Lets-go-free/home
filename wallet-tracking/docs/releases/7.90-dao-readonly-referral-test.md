**Sicherheit:** Kein Cron. Der normale Worker ist durch `DAO_REWARD_ENABLE_LIVE_WORKER` (Standard: deaktiviert) gesperrt. Der reine Lese-Test benötigt zusätzlich `DAO_REWARD_ENABLE_TEST_INSPECT=true` und den bestehenden Header `x-wallet-refresh-secret` mit `WALLET_DAILY_REFRESH_SECRET`. Nur diese fest konfigurierte Adresse wird gesucht. Der Aufruf führt keine Schreiboperationen aus.

## Einmaliger manueller Test

1. Edge Function `dao-reward-refresh` mit `Verify JWT` aktiviert bereitstellen. Für service-seitige Aufrufe gültiges JWT im `Authorization: Bearer ...` Header verwenden. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `WALLET_ENCRYPTION_MASTER_KEY_V1`, `WALLET_DAILY_REFRESH_SECRET` müssen vorhanden sein.
2. Secret `DAO_REWARD_ENABLE_TEST_INSPECT=true` setzen. `DAO_REWARD_ENABLE_LIVE_WORKER` ausdrücklich **nicht** auf true setzen.
3. Per Supabase Edge Function Test/HTTP POST mit JSON `{"mode":"inspect-test-wallet"}` und Header `x-wallet-refresh-secret: <WALLET_DAILY_REFRESH_SECRET>` aufrufen.
4. Ergebnis auf `matchingWallets`, `transactions`, `incomingFlows`, `candidateClaims`, `cursors` und `queue` prüfen. Keine User-ID oder Wallet-ID wird ausgegeben.
5. Nach der Prüfung `DAO_REWARD_ENABLE_TEST_INSPECT=false` setzen oder entfernen. Kein Cron einrichten.

Dieser Readiness-Test prüft die **vorhandenen Supabase-Daten**, nicht die Vollständigkeit aktueller Blockchain-Daten. Er verarbeitet keine neuen Claims und ändert keine Rewards. `matchingWallets=0` bedeutet, dass keine passende entschlüsselbare registrierte Wallet gefunden wurde; die Adresse kann auch nur als Referral-Wallet in der Anwendung konfiguriert sein.
