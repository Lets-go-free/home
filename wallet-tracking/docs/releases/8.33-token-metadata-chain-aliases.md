# Phase 8.33 – Gemeinsame Chain-Aliase für Token-Metadaten

Stand: 14.11.2026 10:04:32 CET

## Ursache
`predefined_tokens.chain` enthält sowohl registrierte Namen als auch UI-Namen. Fehlende Registry-Aliase führten zu `unknown-chain` bei technischen Metadatenprüfungen.

## Korrektur
- `arbitrum` → `arb` (42161), `avalanche` → `avax` (43114), `polygon` → `matic` (137), `solana` → `sol`.
- Nur Registry-Lookup über Aliase; bisherige Chain-Keys in `predefined_tokens`, `safe_tokens`, internem Metadaten-Cache und Wallets bleiben unverändert.
- SQL-Funktion `wallettracking_metadata_address` nutzt dieselben Aliasregeln wie die Edge Function.
- EVM: on-chain `eth_chainId` und `decimals()` bleiben erforderlich. Solana: Mint-Konto und Owner-Prüfung bleiben erforderlich. Technische Verifizierung ist kein Sicherheitsnachweis.

## Installation
1. Projekt-ZIP einspielen.
2. Einmalig Migration `20261114100432_token_metadata_chain_aliases_833.sql` ausführen.
3. Edge Function `token-metadata/index.ts` neu deployen.
