# 9.65 – Historischer SmartNode-Parent-RPC-Vergleich

Build 20261122-212418 · 22.11.2026 21:24:18 CET.

Da derzeit keine neuen Referral-Mints eintreffen, kann die 9.64-Pfadprüfung nicht allein anhand der bestehenden 5-Minuten-Jobzähler getestet werden. `historical-smartnode-parent-rpc-check` wählt read-only maximal eine bereits verifizierte historische Elternbeziehung aus `tln_vow_smartnode_graph_cache` und nutzt den **gleichen** Getter-/Join-On-Chain-Fallback aus der aktiven Serververarbeitung.

Das Ergebnis ist anonym (`sameParent`, Status, gewählte Methode). `parent_agreement` belegt Übereinstimmung mit **einer** global gespeicherten Parent-Beziehung zum Abfragezeitpunkt. `parent_disagreement` kann einen veralteten Graph oder geänderte On-Chain-Beziehung bedeuten. `onchain_unresolved` bedeutet unzureichende RPC-/Getter-/Join-Evidenz, nicht «keine Beziehung». Sind keine verifizierten Kanten vorhanden, wird keine RPC gestartet.

Einrichtung: ZIP installieren, `tln-vow-reward-refresh` neu deployen; anschliessend mit vorhandener Cron-Authentifizierung folgenden POST-Body senden:

```json
{"mode":"historical-smartnode-parent-rpc-check"}
```

Keine SQL-Migration, keine Datenbank-Writes, kein automatischer Job, keine Reward-/Claim-Zuordnung und kein unabhängiger Vollständigkeitsnachweis. Tages-Rewards-Cron bleibt inaktiv.
